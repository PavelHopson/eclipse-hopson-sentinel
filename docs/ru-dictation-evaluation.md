# Русская диктовка: воспроизводимый локальный тест

Срез 28.08.2026. Пользователь утвердил порядок: изоляция агентов → русская диктовка → безопасный монтаж.
JSON-оценщик не включает микрофон, не вызывает модели и не отправляет аудио в облако.
Отдельный явный smoke запускает только уже установленные локальные TTS/STT на синтетических фразах.
Проверяющий скрипт записи по умолчанию также инертен; локальный STT требует отдельного `--run`.

## Что исправлено в работающей цепочке

В `dashboard/electron/ultron-live-voice.cjs` VAD-блок теперь собирается между совпадающими
START/END, даже когда процесс отдаёт его разными порциями. Служебные строки и незавершённые
фразы не становятся сообщениями. Sliding-window режим сохраняет последний redraw строки.

Пауза и echo guard делают незавершённый VAD недоставляемым до конца блока; stop запрещает
доставку. Переполнение отбрасывает строку/блок, не превращает обрезанный хвост в команду.
Обычный текст в скобках не удаляется как таймкод; `-5` и `5` не считаются одним повтором.

Это исправление обработки вывода, не обучение Whisper. Голосовые действия по-прежнему
требуют отдельного ручного подтверждения. Установленная desktop-версия этим diff не обновлена.
Аргумент пути к модели передаётся относительно каталога Whisper: файловый CLI завершался
с кодом `3221226505` при абсолютном пути с кириллицей, а с относительным путём прошёл smoke.
Тот же совместимый вариант закреплён для live runtime; новый микрофонный прогон ещё нужен.

## Запуск без записи

Из корня Sentinel, Node.js 20+:

```powershell
npm run test:voice
npm run eval:voice
node scripts/voice-dictation-eval.mjs --template
```

Без аргументов отчёт показывает 30 отсутствующих результатов и `null` вместо WER/CER,
задержки и стоимости. `--template` печатает незаполненный JSON, но ничего не записывает.

## Реальный прогон — следующий gate

1. Взять [30 оригинальных тестовых фраз](../scripts/fixtures/ru-dictation-v1.json).
   Группы: отрицания, числа, имена проектов, смешанная RU/EN-речь, паузы и фоновый шум.
   Фразы искусственные, не содержат клиентских данных. Группа `noise` означает условие
   будущей записи, а не уже проверенное качество распознавания шума.
2. Записать один согласованный набор локально. Не использовать чужие голоса без согласия,
   реальные пароли, личные сообщения, платёжные или клиентские сведения. Для каждого файла
   отдельно сохранить локально SHA-256, длительность, условия записи и согласованный срок удаления.
3. Сначала прогнать текущий локальный Whisper по инструкции ниже. Не менять аудио между
   кандидатами. Микрофон запускает человек, скрипт читает только явно выбранный файл.
4. Для другого адаптера или сводного сравнения заполнить JSON-шаблон:
   `source: "recorded"`, `status: "ok"`, `text` — фактический вывод модели.
   `latencyMs` — время от передачи готового аудио до готового текста; не время произнесения.
   Неизвестные latency/cost остаются `null`. Пропуск: `missing`; сбой: `error`; отмена:
   `cancelled`. Для этих состояний текст строго `null`.
5. Передать локальный JSON до 128 КБ:

```powershell
node scripts/voice-dictation-eval.mjs --results "E:\путь-к-тесту\whisper-results.json"
```

Команда читает только этот JSON, не читает аудио, не выполняет команды и не пишет файлы.
Отчёт содержит фиксированные case IDs и численные показатели, но не распознанный текст.
Входной JSON содержит текст: не коммитить его и удалять вместе с записями по согласованному сроку.

## Один записанный WAV → локальная проверка → метрики

Для Windows добавлен `scripts/voice-recorded-eval.mjs`. Без аргументов он выводит только
три стартовые фразы. Сначала проверка файла, затем отдельное явное разрешение на STT:

```powershell
npm run eval:voice:recording
node scripts/voice-recorded-eval.mjs --check --case ru-01 --input "E:\согласованные-записи\ru-01.wav"
node scripts/voice-recorded-eval.mjs --run --case ru-01 --input "E:\согласованные-записи\ru-01.wav" --runtime-root "E:\путь\Eclipse AI Runtime" --allow-local-transcription
```

Поддерживается только **WAV PCM16, mono, 16 000 Гц**, от 0,25 до 30 секунд, до 2 МиБ.
Расширение файла не считается проверкой: RIFF, размеры блоков, PCM-формат и длительность
проверяются по байтам. MP3/M4A/stereo и повреждённые WAV отклоняются без автоматической
конвертации. Исходник не меняется. Новые модели не скачиваются.

`--check` не читает runtime и не запускает процесс. `--run` удаляет метаданные WAV в
отдельной временной копии и передаёт её фиксированному `whisper-cli.exe` с моделью
`ggml-large-v3-turbo-q5_0.bin`. URL, UNC/device paths, ADS, `..`, symlink и Windows junction
не допускаются. Shell не используется, timeout — 60 секунд, stdout/stderr ограничены.
API-ключи из окружения не передаются. После обычной ошибки, отмены или успеха временная
копия удаляется; авария ОС/kill требует проверки остатка `.voice-recording-*`. Каталог
добавлен в `.gitignore`, но это не механизм очистки и не защита от другого процесса того же пользователя.

В отчёте — WER/CER, критические ошибки, задержка, SHA-256 аудио, исполняемого файла и модели;
нет полного локального пути и распознанного текста. Хеширование модели не включается в latency:
измеряется запуск Whisper и получение результата, вместе с загрузкой модели. Стоимость
остаётся неизвестной (`null`), а не «бесплатной». Хеши — идентификация тестового набора,
не подтверждение безопасности native runtime/DLL.

Один вызов проверяет один case ID; остальные 29 остаются `missing`. `source: recorded`
обозначает входной файл, не доказательство происхождения голоса: `humanProvenanceVerified: false`.
Перед приёмкой человек подтверждает, что это согласованная человеческая речь, и разбирает
результат. `promotionAllowed` остаётся `false`. Фактических человеческих записей ещё нет.
Это инженерный CLI доверенного оператора, **не инструмент агента и не OS/network sandbox**.

## Как читать результат

- **WER/CER** — суммарное расстояние редактирования / число эталонных слов или символов.
  Это не среднее процентов коротких и длинных фраз. Возможны значения выше 1 при вставках.
- Нормализация: регистр и `ё/е`, внешняя пунктуация; числа, ведущие нули и знаки сохраняются.
  Десятичная запятая и точка эквивалентны. Слова «пятнадцать» не приравниваются автоматически к `15`:
  числовые случаи требуют ручного разбора, это консервативный тест, не семантический судья.
- **criticalFailures** — несовпадение чисел или отмеченных слов/фраз (например, «не»).
  Это индикатор проверки, не исчерпывающая оценка смысла. Неизвестная ошибка не считается безопасной.
- **p50/p95** считаются только по известным задержкам успешных распознаваний; рядом указано число измерений.
- **knownCostUsd** — известная часть стоимости. `costComplete: false` запрещает трактовать
  её как итоговую цену. Известные расходы сбоя/отмены тоже включены; у отсутствующего результата
  не может быть выдуманной цены или задержки. Электричество, hardware cost и цена минуты здесь не вычисляются.
- Синтетические ответы проверяют оценщик, не модель. Даже полный recorded-отчёт остаётся
  `awaiting-human-review`, `promotionAllowed: false`. Порог качества и human review отдельные.

## Синтетический audio smoke: выполнен локально

```powershell
node scripts/voice-local-smoke.mjs
node scripts/voice-local-smoke.mjs --run --runtime-root "E:\путь\Eclipse AI Runtime" --ffmpeg "E:\путь\ffmpeg.exe"
```

Без аргументов — dry-run. С `--run` — три фиксированные фразы (`ru-01`, `ru-07`, `ru-14`):
установленный Piper Denis → WAV validation → FFmpeg 16 kHz → Whisper large-v3-turbo q5_0.
Новых программ/моделей скрипт не скачивает. Это локальная инженерная CLI, не предоставленный
агенту инструмент: путь к бинарникам задаёт доверенный оператор. Нет утверждения об OS sandbox.
Процессы имеют 60-секундный timeout, ограниченный stdout/stderr и сокращённую среду без API keys;
при обычной отмене SIGINT/SIGTERM/ошибке удаляются только временные WAV этого запуска.
При аварийном завершении ОС или принудительном kill может потребоваться ручной scoped cleanup.

[Отчёт smoke от 28.08.2026](evidence/ru-dictation-synthetic-2026-08-28.json): 3 из 30 случаев,
WER 18,75%, CER 16,05%. Отрицание и числа совпали, названия проектов в `ru-14` — нет.
Ошибку нельзя приписать только STT: синтетическое произношение Piper также требует проверки.
p50 1,253 с и p95 12,417 с включают запуск процесса/загрузку модели; это три измерения,
не оценка скорости живого разговора. Полная цена не измерена.

Аудио и транскрипты не сохранены; в evidence только хеши и численные показатели.
Это **проверка работоспособности цепочки**, не benchmark человеческой русской речи и не основание
включить облако/автовыполнение. Для основной приёмки остаются 30 согласованных человеческих записей.

## Границы безопасности и оставшаяся работа

Проверено локально: 60 focused Node checks (42 voice/security + 18 соседних operator/TTS/action),
`dashboard` build и lint, синтаксис CJS и `git diff --check`. Новые parser/evaluator тесты включены
в существующий CI job без новых actions и сетевых тестов; сам удалённый CI ещё не запускался.
14 из 42 проверок относятся к новому WAV-runner: неверные форматы, дубли блоков, ссылки/junction,
отмена, очистка, сохранение оригинала, bounded argv и отсутствие текста в отчёте. В этих
тестах native runtime заменён тестовым адаптером; это не проверка точности Whisper.
SBOM production-зависимостей dashboard: CycloneDX 1.5, 118 компонентов. `npm audit --omit=dev`
вернул 0 advisories. Это не аудит Sentinel Core, native Whisper/Piper, модели или всех devDependencies;
Syft/Grype/NVD cross-validation не выполнялись. Зависимости и lockfile не менялись.

- **Critical:** в этом изменённом контуре не установлены; полного pentest не было.
- **High, открытый release gate:** OS/process/network isolation и права агентов проверяются
  отдельно. Исправленный парсер не даёт права автоматически выполнять распознанные команды.
- **Medium, исправлено локально:** преждевременная доставка VAD, потеря bracketed отрицаний
  и знака числа при подавлении повторов; добавлены отрицательные регрессии.
- **Medium, не измерено:** точность русского STT, устойчивость к шуму, работа реального
  микрофона и TTS-эха. Нет ни одной реальной записи в текущем отчёте.
- **Low, ограничено:** оценщик требует строгий JSON, известные IDs, не более 30 результатов,
  1000 символов на текст и 128 КБ на файл; ошибки не печатают входной текст или пути.

Для Gemini нужен отдельный opt-in: точная модель, endpoint, передаваемые данные, срок хранения,
бюджет и запрещённый скрытый fallback. Наличие ключа не считается согласием. Jot/Palmier и
сторонние пакеты в этот контур не устанавливаются.
