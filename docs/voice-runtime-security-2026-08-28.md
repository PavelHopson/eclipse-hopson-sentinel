# Голос Ultron: защищённый кандидат runtime и Лилит

> Исторический отчёт этапа исследования. Последующее внедрение единственного Альтрона,
> AppContainer и локальная установка 1.2.10 описаны в [отчёте обновления](ultron-1.2.10-voice.md).
> Указанные ниже «установки нет» и отсутствие OS sandbox относятся к прежнему этапу.

Дата проверки: 28 августа 2026. Статус: **runtime-кандидат подготовлен; оставить только Альтрон; Лилит отменена; установки нет**.

Последующая слуховая оценка пользователя: «Голос вообще не похож». Успешные WER/level
проверки ниже не подтверждают сходство или пригодность голоса. Затем пользователь полностью
отменил Лилит и переключатель. Женские пробы сохраняются как история, не для установки.

Пользователь одобрил подготовку безопасности, сохранил выбор `06-angry.mp3` для
Альтрона и уточнил женский образ: Лилит из Diablo, соблазнительная дьяволица.
Для пробы выбран самостоятельный взрослый женский голос: низкий, спокойный,
властный, с мягкой хрипотцой. Это творческое направление, не клонирование актрисы
и не измеренное сходство с персонажем. Файлы фильма не использовались в синтезе.

## Что действительно сделано

- Отдельный Python 3.12 venv в `reports/voice-runtime-2026-08-28/venv`.
  Общий AI Runtime, установленный Ultron 1.2.9/Piper и работающие Ollama не изменены.
- Вместо уязвимого pin Transformers 4.57.3 подготовлен небольшой локальный fork
  Qwen с **Transformers 5.16.1**, torch 2.11.0 CPU, torchaudio 2.11.0,
  accelerate 1.12.0, librosa 1.0.0, soundfile 0.14.0 и einops 0.8.2.
- Зависимости установлены из wheels. Pip обновлён до 26.2.1. `pip check` проходит.
  Gradio, SoX и неиспользуемая ONNX-цепочка в отдельную headless-сборку не нужны.
- 61 внешний Python-пакет проверен по OSV; локальный fork рассмотрен отдельно.
  CycloneDX содержит 62 компонента и 91 dependency edge. Это не аудит Windows,
  GPU-драйвера, FFmpeg, Whisper и всех нативных библиотек.
- Наследуемые stdin/stdout pipes вместо HTTP-сервера. Нет слушающего порта,
  микрофона, автоматической загрузки моделей, облачного TTS или инструментов агента.
- Разрешены только фиксированные профили и текст: до 240 символов / 2048 bytes.
  Дубликаты JSON-ключей, лишние поля, control characters и служебные Qwen-токены отвергаются.
- Секреты, proxy, `PYTHONPATH` и произвольный `PATH` не наследуются. Python запускается
  с `-I`; shell отключён. Пути runtime/model принадлежат хосту, не renderer.
- Единственный запрос одновременно, предел 360 секунд, stdout 1.8 MB, stderr 8 KB.
  Отмена завершает собственное дерево процессов Windows и ждёт закрытия перед новым запросом.
- Проверены 11 файлов модели общей длиной 2 498 383 610 bytes: имена, размеры,
  SHA-256, отсутствие symlink/junction и опасных полей config. Дополнительные загружаемые
  файлы не принимаются; только закреплённые JSON/TXT/safetensors.
- `local_files_only`, `trust_remote_code=False`, safetensors и SDPA заданы принудительно
  также во вложенном tokenizer. Python network audit hook блокирует DNS/connect/bind/sendto.
- Ответ проверяется как ограниченный PCM16 mono WAV 24 kHz: заголовки, byte rate,
  block alignment, фактическая длительность, конечные значения и соответствие профиля.
  Достижение лимита генерации считается ошибкой, а не законченной фразой.

**Отдельный venv и Python audit hook — не OS sandbox.** Нативный код всё ещё работает
с правами текущего пользователя. Политика firewall/AppContainer/ограниченного токена
не установлена. Нельзя рекламировать эту сборку как полностью изолированную или
подключать к ней произвольные модели/плагины. Общий Python не блокировали firewall,
поскольку это могло бы затронуть другие процессы пользователя.

## Совместимость: обнаруженный и исправленный дефект

Upstream Qwen 0.1.1 жёстко требует старую версию Transformers. Одного изменения
dependency pin недостаточно. Локальная совместимость включает новые mask APIs,
декоратор, default RoPE, восстановление cache position и безопасные nested loads.

Первый полный синтез загрузил модель без исключения, но выдал 23.92 s неразборчивого
аудио с WER 1.0. Такой результат **отбракован**, не установлен и не выдан как готовый голос.
Численная диагностика показала неинициализированные nonpersistent RoPE buffers после
meta-loading Transformers 5. В fork добавлено восстановление строго трёх классов
Qwen RoPE по исходной формуле. Реальная повторная загрузка подтвердила точное совпадение
всех трёх частотных буферов; отдельные regression tests воспроизводят этот дефект.

После исправления получено 9.2 s исходной речи; обе обработанные версии распознаются
локальным Whisper без словесных ошибок на одной проверочной фразе. Upstream не заявляет
поддержку нашего fork: дальнейшие обновления требуют повторной численной и звуковой QA.
Сохраняются upstream deprecation/docstring warnings; production readiness ими не доказана.

## Security findings: не смешивать старый runtime и новый кандидат

| Уровень | Находка | Статус |
| --- | --- | --- |
| Critical | В проверенной поверхности подтверждённых Critical не установлено | Не означает отсутствие неизвестных проблем |
| High | [CVE-2026-4372 / GHSA-29pf-2h5f-8g72](https://github.com/advisories/GHSA-29pf-2h5f-8g72): вредоносный attention config может загрузить чужой код в Transformers <5.3 | В новом кандидате используется 5.16.1, опасные config-поля отвергаются. **В старом общем venv 4.57.3 проблема остаётся**, он не исправлялся и не подключён как новый голос |
| Medium (MODERATE upstream) | [setuptools MANIFEST.in bypass](https://github.com/advisories/GHSA-h35f-9h28-mq5c), setuptools 81.0.0 | Не устранено. Advisory про sdist и Unicode-нормализацию macOS; здесь Windows/wheels. Torch требует setuptools <82. Ограниченная применимость, не автоматическое разрешение production-релиза |
| Medium, архитектурный риск | Нет OS-level ограничения нативного процесса и полного native supply-chain scan | Открыто до постоянной интеграции; pipes/offline flags не заменяют sandbox |
| Low | [torch.jit.script memory corruption](https://github.com/advisories/GHSA-rrmf-rvhw-rf47), torch 2.11.0 | Не устранено. Пользовательский TorchScript, код и checkpoint conversion не принимаются |

OSV вернула три записи, соответствующие **двум различным advisories**: GHSA/PYSEC aliases
setuptools считаются одной находкой. В новом Python inventory High/Critical совпадений
нет; это результат на момент проверки, не сертификат безопасности. Утечек секретов в
добавленных исходниках/манифестах не выявлено; вывод текста ограничен локальными
first-party audition reports, рабочий worker не пишет пользовательский текст в логи.

## Воспроизводимость и источники

Первичный источник: [официальный Qwen3-TTS](https://github.com/QwenLM/Qwen3-TTS),
[PyPI qwen-tts](https://pypi.org/project/qwen-tts/). Основа — wheel 0.1.1, Apache-2.0.
Не выполнялся сторонний installer; Apache license сохранена в `QWEN-LICENSE`.
Веса существующей модели закреплены локальным хешем, не новой upstream-подписью.
Веса, venv и аудио не входят в Git.

В `scripts/voice-runtime/` сохранены `qwen-compat.patch`, `qwen-pyproject.toml`,
`requirements-win-py312.lock`, `model-lock.json`, worker/supervisor и тесты.

Для повторной сборки: проверить hash исходного wheel, распаковать в отдельный каталог,
просмотреть/применить патч с `--ignore-space-change`, добавить данный pyproject и LICENSE.
В отдельном Python 3.12 x64 venv ставить lock только с `--require-hashes --only-binary=:all:`.
Собирать собственный wheel через `pip wheel --no-deps --no-build-isolation`, после установки
обязательно `pip check` и все приведённые тесты. Hash wheel выше относится к фактически
проверенному артефакту: без нормализации build timestamps новая сборка не обязана совпасть побайтно.
Автоматический скачиватель/установщик для пользователя пока не выпускается.

## Что осталось до подключения единственного голоса Альтрона

1. Проверить одобренный Uncle_Fu + точный DSP `06-angry` на новом runtime; сохранить
   исходный одобренный пробник неизменным. Лилит больше не входит в план.
2. Решить latency и измерить выбранный мужской профиль. Полученные ранее 67.453 s
   на 9.2 s женского аудио не являются измерением Альтрона и не подтверждают realtime.
   GPU не освобождалась за счёт других моделей.
3. Завершить OS-level isolation и review native dependencies; закрепить доверенные
   пути/целостность runtime в подписанном host package. Нельзя принимать пути от renderer.
4. Подключить bounded IPC и доверенную DSP-обработку: текущий worker отдаёт сырой PCM,
   эффекты применены только к пробникам. Отсутствие Qwen не должно молча включать Piper.
5. Оставить один голос с понятными «Послушать» и stop, без переключателя персонажей.
   Прослушивание не включает микрофон и не меняет модель, память или approvals.
6. Повторить desktop/mobile/a11y QA при изменении интерфейса. В этом изменении UI нет.

Использованные security skills: `analyzing-sbom-for-supply-chain-vulnerabilities`
определил inventory/hash/advisory проверки; `conducting-api-security-testing` — строгий
контракт локального канала, негативные тесты, лимиты и отмену. Активных внешних атак,
production deployment, git commit/push и изменения общего runtime не выполнялось.
